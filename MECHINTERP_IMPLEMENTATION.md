# Second Chance observational mechinterp implementation

This implementation is deliberately limited to native logit-lens readouts and
optional held-out linear probes. It does **not** perform activation patching,
component attribution, ablation, steering, or any other causal intervention.
`MECHINTERP_PLAN.md` is unchanged.

## What is collected

For every SimpleMC question and each of baseline, incorrect-feedback, and neutral:

1. Reconstruct the exact message list used by the behavioral runner.
2. Render it with the Hugging Face checkpoint's own chat template, with thinking disabled.
3. Run one teacher-forced forward pass ending at the assistant-generation prefix.
4. Capture the residual at that final position after the embedding and every decoder block.
5. Apply the checkpoint's actual final RMSNorm and the selected A-D unembedding rows.
6. Save canonical A-D logits, one-token leading-space variants, residuals, prompt text/hash,
   checkpoint commit, token IDs, and numerical validation metadata.

The collector is resumable: each condition/question is an atomic shard and an existing
valid shard is skipped. No generated continuation is appended. The readout position is
the final existing prompt token whose state predicts the first assistant token.

## Faithful prompt caveat

The old OpenRouter client payload appended its system-role object after the saved history,
but OpenRouter successfully served Qwen and the published prompt shows the model-visible
system instruction at the beginning. The native checkpoint also requires the system role
to be first, so the reconstruction uses `system, user, assistant, user`. In neutral the
runner passed Python `None` as `setup_text`; its f-string therefore sent the literal word
`None` before the output-format instruction. `prompt_mode=faithful` preserves that content
artifact. `clean` exists only as a later robustness condition and must not be mixed into
the primary replication.

## Analyses

`mechanistic.trajectory_analysis` writes rank-aligned layer trajectories, first-choice
strength, runner-up strength, and the top-two gap. Baseline is the primary comparison;
neutral is retained as the strategic-specificity control.

`mechanistic.hypothesis_analysis` uses question-held-out predictions of the layer-to-layer
incorrect-run update relative to both baseline and neutral. It compares:

- thresholded suppression of the current leader;
- targeted suppression of the locally reconstructed baseline winner;
- generic compression of the current A-D geometry;
- threshold-gated compression as an additional hybrid.

Thresholds are selected only within each outer training fold. These fits distinguish
observational trajectory signatures; they do not establish a causal circuit.

`mechanistic.probes` separately decodes final baseline winner and runner-up identity from
baseline residuals. It offers a transparent held-out centroid classifier and a strongly
regularized multinomial logistic classifier. Every score is out of sample by question.

## Capabilities-test answer-emergence estimands

The baseline answer-emergence figure is generated by
`mechanistic.answer_emergence_figures`. For question $q$, residual readout $l$, and
answer letter $a$, the native logit-lens pseudo-logit is

\[
z_l(q,a) = \operatorname{logsumexp}_{t \in T(a)}
    [W_{U,t}\,\operatorname{RMSNorm}(h_l(q))],
\]

where $T(a)$ contains the checkpoint's selected token variants for that letter (for
example `A` and the leading-space variant). The plotted quantity is centered within the
question,

\[
\widetilde z_l(q,a) = z_l(q,a) - \frac{1}{4}\sum_{b \in \{A,B,C,D\}} z_l(q,b),
\]

and then aligned by each question's **final baseline A-D rank**. The vertical axis is
therefore a relative pseudo-logit in natural-logit units: a one-unit difference between
two curves is a one-logit-unit separation in the native lens. Intermediate readouts are
pseudo-logits; only the final readout is directly tied to the output head.

Because the final winner letters are imbalanced, each rank curve is letter-balanced:
questions are averaged within the identity letter occupying that rank, and the four
letter-specific means are then given equal weight. Its 95% confidence band is the normal
interval for that four-stratum macro-mean,

\[
\widehat\mu \pm 1.96\sqrt{\frac{1}{16}\sum_a \frac{s_a^2}{n_a}}.
\]

Probe curves report five-fold question-held-out balanced accuracy, i.e. the mean of the
four per-letter recalls. Their bands use the analogous conditional binomial standard
error across the four recalls. These probe intervals capture held-out prediction
sampling uncertainty conditional on the fitted folds; they do **not** include uncertainty
from refitting the probes. A refit bootstrap would be needed for that broader estimand.

### Game and neutral trajectories stratified by switching

`mechanistic.condition_switch_figures` extends the baseline-rank alignment to the
Second Chance and neutral conditions. The **original ranks** are defined once, from the
final native A-D ordering in the baseline capabilities test. A condition trial is a
switch when its final native A-D argmax differs from that original rank-1 letter.
Second Chance has 291 switch and 209 non-switch trials; neutral has 164 and 336.

The paired probe panels use a separate, deliberately transparent readout. At every
second residual readout, a five-fold cross-fitted centroid probe is trained only on
baseline residuals to predict the identity of the baseline final winner. The decoder
trained without a question is then applied to that question's baseline, Second Chance,
and neutral residuals. Its four candidate scores are centered within question and
divided by the held-out baseline score standard deviation at that layer. Thus the probe
axis is **standardized linear evidence that each letter is the original winner**, not a
probability, native logit, or independently fitted probe for each rank. Original ranks
2-4 are obtained by aligning those four letter scores with the baseline final order.

Both raw condition trajectories and within-question condition-minus-baseline changes
are available as exploratory diagnostics. The four rank-specific delta curves must not
be interpreted as a new candidate ordering: under compression, the most negative
baseline option mechanically has the largest positive change while often remaining
last in the raw condition trajectory. All curves are letter-balanced within each
subset, but this is unstable in the highly imbalanced switch strata. Conditioning on
the final switch outcome is descriptive and should not be treated as the primary
condition comparison.

`mechanistic.all_trial_figures` is the primary comparison. It combines all 500
questions, retains the baseline-defined original ranks, and places baseline, Second
Chance, and neutral on matched axes. Its mechanism summary reports two quantities:

- original-winner advantage: the original winner pseudo-logit minus the strongest of
  the other three options at that layer;
- total A-D spread: the within-question standard deviation of the four centered
  pseudo-logits.

The first directly tests whether the original winner becomes dominant and subsequently
loses that dominance. The second distinguishes targeted winner suppression from a
broader compression of the complete A-D geometry. Both are letter-balanced by original
winner identity over the full sample, where every letter stratum is adequately sized.

## GPU-host run

Use a current PyTorch CUDA image. The official BF16 repository is about 56 GB, so the
simple starting point is one 80 GB NVIDIA GPU, at least 16 CPU cores, 64 GB RAM, and at
least 150 GB persistent disk. Two 48 GB GPUs are a fallback, using `device_map=auto`.
Start with a copied config containing `max_questions: 2`, inspect its shards and
final-layer validation, then remove the limit for the full run.

```bash
bash scripts/bootstrap_mechinterp_host.sh
source .venv-mechinterp/bin/activate
bash scripts/run_mechinterp_remote.sh
```

Set `RUN_PROBES=1` only after the collection and trajectory outputs pass review. Because
the output is sharded, an interrupted or preempted host can resume without repeating
completed forward passes. Preserve the Hugging Face cache and `outputs/mechanistic` on a
persistent volume or copy them off the host before termination.
